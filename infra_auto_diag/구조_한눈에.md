# 구조 한눈에 — dist(들고 가는 것) vs src(만드는 공장)

파일이 많아 보여도 실제로 **타깃에 들고 가서 돌리는 건 몇 개뿐**이다.
나머지는 그 몇 개를 **찍어내는 공장(소스 + 생성기)** 이다. (exe는 1개, 소스 레포는 수백 개인 것과 같음)

```
[src: 소스·양식·생성기]  ──build_*.py──►  [dist: 단일파일 deliverable]  ──들고 감──►  타깃에서 실행
```

---

## 📦 DIST — 실제로 들고 가서 돌리는 것 (이것만 배포/S3 업로드)

| 파일 | 어디서 돌리나 | 무엇 |
|---|---|---|
| **`kisa_all_check.ps1`** | 각 서버(리눅스 bash·윈도우 PS) | 인프라+웹 통합 점검(개별 스캐너 4개 내장) → CSV |
| `db_oracle_check.sh` | DB 서버 | Oracle 점검 → CSV |
| `cloudscan_all.py` | 자격증명 있는 곳 | 클라우드 점검(양식 내장) → CSV/xlsx |
| **`makereport_all.py`** | 분석 PC(파이썬+lxml) | CSV → 결과보고서 xlsx (엔진+양식8 내장) |

> SSM은 서버에 `kisa_all_check.ps1` **1개만** 내려 돌린다 = "한 스크립트 들고 가서 실행".

---

## 🏭 SRC — dist를 만드는 공장 (타깃엔 절대 안 감, 지우면 재생성 불가)

### (1) 스캐너 소스 → `kisa_all_check.ps1`
| 소스 | 생성기 |
|---|---|
| `kisa_unix_check.sh` (U-01~67, 리눅스 인프라) | |
| `kisa_win_check.ps1` (W-01~64, 윈도우 인프라) | **`build_allinone.py`** |
| `web_linux_check.sh` (WEB, 리눅스 웹) | ↓ 만듦 |
| `web_windows_check.ps1` (WEB, 윈도우 웹) | `kisa_all_check.ps1` |

### (2) 보고서 엔진 소스 → `makereport_all.py`  (이 엔진은 분석 PC에서 직접 써도 됨)
| 소스 | 생성기 |
|---|---|
| `make_reports.py` (폴더 일괄 변환·고정파일명·버전) | |
| `make_report.py` (한 종류 1개 변환 CLI) | **`build_report_onefile.py`** |
| `server_report.py` (양식 채우는 핵심 엔진) | ↓ 만듦 |
| `tpl_xml.py` (xlsx=zip+XML 저수준 편집 라이브러리) | `makereport_all.py` |
| `보고서_양식_*.xlsx` × 8 (공식 양식) | |

> `merge_local.ps1`은 이 엔진(`make_reports.py`)을 분석 PC에서 **직접** 호출한다. 파이썬 없는 곳에선 `makereport_all.py`(단일파일)를 쓴다.

### (3) 클라우드 소스 → `cloudscan_all.py`
| 소스 | 생성기 |
|---|---|
| `cloud_check/` (aws·azure·gcp·ncp + *_items 항목정의 + base) | **`build_onefile.py`** |
| `cloud_scan.py` (클라우드 점검 CLI) | ↓ 만듦 |
| `infra_report.py` (인프라/클라우드 결과 → xlsx, cloudscan_all이 import) | `cloudscan_all.py` |

### (4) 양식 생성기 → `보고서_양식_*.xlsx`
| 생성기 | 무엇 |
|---|---|
| `build_server_templates.py` | 서버·웹·DB 양식 생성/수리 |
| `build_cloud_templates.py` | 클라우드 양식 생성/수리 |
| `make_blank_template.py` | 공식 보고서(데이터 포함) → 빈 양식 |

## 한 줄 요약

- **들고 가는 것 = 📦DIST 4개**(서버엔 `kisa_all_check.ps1`, PC엔 `makereport_all.py`).
- **레포의 나머지 = 🏭공장**(그 4개를 만드는 소스·생성기) → 지우면 수정·재생성 불가.
- 운영 자동화(SSM/S3)는 "점검 로직"이 아니라 **DIST를 올바른 곳에 배치·실행**하는 글루.
