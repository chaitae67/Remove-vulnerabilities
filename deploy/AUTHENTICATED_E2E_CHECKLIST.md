# 인증 필요 웹 취약점 E2E 점검표

운영 개인정보나 실제 결제정보를 사용하지 않는다. 전용 테스트 고객 계정 2개(`USER_A`,
`USER_B`)와 테스트 관리자 계정 1개를 만들고, 점검 후 생성 데이터만 정리한다.

## BF-09 약한 비밀번호 정책

1. 고객 회원가입에서 `1234`, 아이디와 동일한 값, 영문만 10자 이상의 값을 시도한다.
2. 모두 거부되고, 영문·숫자·특수문자를 포함한 10자 이상 값만 허용되는지 확인한다.
3. 비밀번호 재설정 및 회원정보 수정에서도 동일 정책이 적용되는지 확인한다.
4. 운영 관리자 계정이 기본값, 아이디 포함 값, 사전 단어를 사용하지 않는지 별도로 확인한다.

판정: 약한 값으로 계정 생성·변경이 불가능하고 DB에는 BCrypt 해시만 존재하면 양호.

## IA-10 불충분한 인증 절차

1. `USER_A` 로그인 후 `/mypage/edit`에 직접 접근한다.
2. 비밀번호 재확인 화면이 나오고, 재인증 없이 수정 POST를 보내도 변경되지 않아야 한다.
3. 올바른 비밀번호로 재인증한 뒤 5분 이내에만 수정할 수 있는지 확인한다.
4. 저장 시 잘못된 `currentPassword`를 보내면 세션 재인증 이력이 있어도 거부되어야 한다.
5. 결제 요청에서 `accountPassword` 누락·오류 시 주문이 생성되지 않아야 한다.
6. 관리자 공지·회원·상담·결제·기록 변경에서 `adminPassword` 누락·오류 시 변경되지 않아야 한다.

판정: 중요 변경 직전의 서버 측 재인증을 우회할 수 없으면 양호.

## IN-11 불충분한 권한 검증

1. `USER_A`로 비공개 Q&A, 후기, 테스트 주문을 생성한다.
2. `USER_B`로 로그인한 뒤 URL의 글 ID·주문번호·첨부 ID를 `USER_A`의 값으로 변경한다.
3. 비공개 Q&A 본문·첨부, 후기 수정·삭제, 주문 상세가 `403`, `404` 또는 일반 오류로 차단되는지 확인한다.
4. 고객 계정으로 관리자 사이트 로그인을 시도하고, 관리자 계정으로 고객 사이트 로그인을 시도한다.
5. `/admin`, `/api/admin/users` 직접 접근도 차단되는지 확인한다.

판정: UI 표시 여부와 무관하게 서버가 소유자·역할을 재검증하면 양호.

## PV-13 프로세스 검증 누락

1. 후기 작성 요청의 경로만 `/notices`로 변경한다. `403`이어야 한다.
2. 결제 요청에서 화면에 없는 `price` 값을 추가·변조한다. 최종 금액은 DB의 시술 가격으로 계산되어야 한다.
3. `quantity=0`, 보유 포인트 초과, 이미 사용한 쿠폰, 지난 예약일을 각각 전송한다.
4. 카드 결제에서 카드번호·유효기간·카드 비밀번호 앞 2자리 중 하나를 누락하거나 변조한다.
5. `/payments/success/{orderNumber}`를 결제 단계 없이 직접 호출한다.
6. 관리자 공지 작성·삭제가 고객 앱 경로나 일반 사용자 세션으로 수행되지 않는지 확인한다.

판정: 단계 생략·파라미터 변조로 주문이나 공지 상태가 변경되지 않으면 양호.

## FU-14 악성 파일 업로드

실제 악성 코드는 사용하지 않고 무해한 텍스트만 사용한다.

1. 정상 PNG/JPEG/PDF/TXT 업로드가 필요한 화면에서 허용 범위대로 처리되는지 확인한다.
2. `<script>alert(1)</script>` 텍스트를 `fake.png`로 저장해 업로드한다.
3. `test.jsp`, `test.jsp.png`, `test.exe`, 확장자 없는 파일을 업로드한다.
4. 파일명 `../test.png`, `..\test.png` 형태를 프록시 도구로 전송한다.
5. 10MB 초과 파일을 전송한다.
6. 업로드 URL을 직접 열어도 서버 측 코드나 HTML로 실행되지 않는지 확인한다.

판정: 확장자·시그니처·크기·경로 검증이 모두 적용되고 파일이 웹 루트 밖에 저장되면 양호.

## FD-15 파일 다운로드

1. Q&A/후기 다운로드 URL이 실제 파일명 대신 게시글 ID와 첨부 ID만 사용하는지 확인한다.
2. 첨부 ID를 다른 글의 값으로 바꿔 비공개 첨부에 접근한다.
3. 경로 자리에 `../`, URL 인코딩 `%2e%2e%2f`, 이중 인코딩 값을 넣는다.
4. 관리자 기록 다운로드 ID에 64자리 16진수 이외 값을 넣는다.
5. 정상 다운로드 응답이 `Content-Disposition: attachment`, `application/octet-stream`, `nosniff`인지 확인한다.

판정: 허용 디렉터리와 DB에서 연결된 파일만 내려받을 수 있고 경로 입력 자체를 받지 않으면 양호.

## IS-16 불충분한 세션 관리

1. 로그인 전 `JSESSIONID`를 기록한다.
2. 로그인 성공 후 세션 ID가 다른 값으로 변경되는지 확인한다.
3. 로그아웃 후 이전 세션 쿠키로 `/mypage` 또는 `/admin`에 접근한다.
4. 브라우저를 닫거나 30분 유휴 후 기존 세션이 만료되는지 확인한다.
5. 쿠키가 `Secure`, `HttpOnly`, `SameSite=Strict`인지 확인한다.
6. 임의의 `role=ADMIN`, `userId=1`, 위조 `JSESSIONID` 쿠키를 추가해도 권한이 바뀌지 않는지 확인한다.

판정: 로그인 시 세션 ID가 재발급되고 로그아웃·만료 세션이 재사용되지 않으면 양호.

## 증적 보관

각 시험마다 다음만 저장한다.

- 시험 일시와 대상 URL
- 요청 메서드·경로·변조한 파라미터 이름
- 응답 상태 코드와 차단 메시지
- 변경 전후 DB 건수 또는 화면 상태
- 세션·CSRF·비밀번호·개인정보는 전체 값이 아닌 길이 또는 마스킹 값

실제 비밀번호, 세션 ID, CSRF 토큰, 카드번호, DB 접속정보는 증적에 남기지 않는다.
